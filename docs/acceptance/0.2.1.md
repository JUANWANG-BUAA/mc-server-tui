# v0.2.1 acceptance — 2026-10-20

## Decision

Accepted for an **unsigned alpha pre-release** on the existing three-target
matrix. This is not a production-stability or in-game world-integrity claim.

## Personally exercised

The compiled TUI was operated through keyboard input in an 80×24 PTY exposed
by local ttyd and Playwright. A separate daemon, socket, cache, state directory,
and copied Paper instance were used; the original instance was not changed.
The copied server bound only to `127.0.0.1:25671`.

- Paper 1.21.11 build 132, local OpenJDK 27: start reached `Done` / ready.
- A console `say release-0.2.1-acceptance` appeared in the actual server log.
- Instance diagnostics expanded/collapsed; graceful stop exited with code 0.
- Created a stopped-world backup and refreshed the verified catalog.
- Wrote a harmless world marker before backup, changed it afterward, reviewed
  the three-world replacement preview, and explicitly entered `RESTORE`.
- Restore completed directory-tree verification; the marker read
  `before-backup-v0.2.1` again, proving the later content was replaced.
- Explicitly started the restored instance; Paper reached `Done` again.
- The instance was gracefully stopped after the drill.

No Minecraft game client joined. In-game post-restore inspection and real
Linux user-service installation remain open acceptance items.

## Findings fixed before release

- Runtime summary now retains instance name and Minecraft version at both
  80×24 and 40×12; F3 guidance appears only on the applicable wizard step.
- Backup loading titles and explanations now describe creation, verification,
  preview or restoration instead of calling every operation a catalog read.

## Automated evidence

- `cargo test --workspace`: 224 passed, including 98 TUI tests.
- `cargo fmt --all --check`, strict workspace Clippy, and workspace build passed.
- Four PTY suites passed: responsive shell, guided create, task detail, and
  instance/backup/restore/lifecycle interaction. Instance suite was repeated
  after the backup copy fix; TUI tests and Clippy were repeated after final edits.
- `scripts/check_protocol_window.py`: actual isolated daemon accepted v8–v11
  and rejected unsupported operations/versions.

## Visual evidence and harness limits

The v0.2.1 website screenshots capture the actual TUI using deterministic
responses from `scripts/tui_visual_fake_daemon.py`. Their server metrics,
progress and backup metadata are illustrative, not benchmark evidence.
Seven themes, guided creation, runtime summary and backup impact were reviewed.

The browser terminal's WebGL renderer initially produced incorrectly scaled
captures; the DOM renderer and a viewport fitting all 80 columns were used.
An initial start failed because the copied fixture omitted its `logs` directory;
restoring that directory resolved it. Neither issue was a shipped-app defect.
