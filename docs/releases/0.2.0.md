## Your server, without another web panel

`mc-server-tui` turns one terminal into the control room for a small Minecraft
host: create a Paper or Fabric server, watch downloads byte by byte, follow the
console, manage players, edit common settings, restart cleanly, and restore a
checksummed world backup. The management UI and daemon can restart without
taking Java down with them.

No browser. No root. No random daemon left inside a closed terminal tab.

## What’s new in 0.2.0

- **Paper + Fabric creation** with official metadata, exact build locking,
  resumable downloads, size/hash verification, Java and port checks, and an
  explicit EULA step.
- **A real daily-management workspace** with stable pages, live logs, regex
  search, filtering, CPU/RSS history, connection guidance, player actions, and
  non-destructive alerts.
- **Mods, plugins, and server packs** through Modrinth add-on installation,
  MRPACK/ZIP preview, stopped-server import, and checksummed server-pack export.
- **A focused `server.properties` editor** for MOTD, max players, difficulty,
  and view distance, with diff review, concurrent-edit detection, and atomic
  save.
- **Controlled restart** through `/restart` or `R`, plus
  `mc cli instance start/stop/restart`. The old process must exit cleanly
  before the replacement starts.
- **Actionable startup failures** for incompatible Java, occupied ports,
  unaccepted EULA, Java heap exhaustion, and missing/corrupt `server.jar`.
- **Protocol v11 with v8–v11 compatibility**, runner protocol v1, versioned
  manual update status, rollback, and state-schema downgrade checks.

## Install

`v0.2.0` is a pre-release, so use the tag-specific installer:

```sh
TAG=v0.2.0
curl -fsSL "https://github.com/JUANWANG-BUAA/mc-server-tui/releases/download/$TAG/install.sh" | sh
mc setup
mc
```

The installer checks the release manifest hash and size, then installs a stable
launcher and versioned binaries under your user account.

## Known limitations

- Unsigned and unnotarized artifacts; no Homebrew tap, apt/dnf repository, or
  signed automatic updater yet.
- No Vanilla provider and no takeover of an existing server directory.
- `server.properties` coverage is limited to MOTD, maximum players, difficulty,
  and view distance; raw editing and the full property catalog are pending.
- Backups are stopped-world only; scheduled/online backups remain pending.
- Forge/NeoForge and CurseForge file-ID materialization are not implemented.
- A Minecraft-client join and post-restore in-game world verification still
  need a real client drill.
- Linux systemd is covered by CI tests but still needs a real-host service
  installation drill.
- State migrations and update-time task draining are not implemented.
