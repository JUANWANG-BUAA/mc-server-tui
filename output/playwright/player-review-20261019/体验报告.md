# mc-server-tui：准备和朋友联机的实际体验

体验时间：2026-10-19。只阅读 README 和程序命令行帮助，没有阅读实现代码、设计文档或既有测试脚本。通过本机 ttyd 在浏览器中操作真实 TUI，观察实际画面并验证操作结果。评估了 1200×800 和 800×490 两种窗口；后者约为 80 列的终端。

结论：服务端管理的主要操作可以实际完成，但“我想和朋友玩”尚未形成完整的用户旅程。最大的缺口是首次配置、任务结果反馈，以及启动成功后怎样让朋友加入。视觉问题集中在主次层级、低对比文字、状态不一致和空间分配。

## 实际操作及结果

| 玩家要做的事 | 实际结果 |
| --- | --- |
| 首次启动，输入 `/create` | 默认 User-Agent 被拒绝，创建向导无法继续。通过 `setup --user-agent` 设置项目所有者的 GitHub 联系地址并重启 daemon 后继续。 |
| 创建朋友联机服务器 | 实际创建 `friends-night`，Paper 1.21.11 build 132，Java 27，2–4 GiB，端口 25565。下载 52.3 MiB，任务成功。 |
| 查看进度和启动 | `/tasks`、`/task 1` 可查看下载。`/start` 成功，日志出现 Done，界面进入运行中。 |
| 验证是否真有 Minecraft 服务 | 实际发送 Minecraft Server List Ping，返回 Paper 1.21.11、协议 774、0/20 玩家、默认 MOTD。并非只检查 TCP 端口。 |
| 发送控制台命令 | 发送 `list`，日志实际返回 `There are 0 of a max of 20 players online:`。 |
| 运行中备份 | 任务提交被接受，随后失败，原因是必须先停服。 |
| 正常停服后备份 | 停服成功，退出码 0；实际创建 35 个文件、约 6.3 MiB 的世界备份。 |
| 校验、预览及恢复 | 单独复验通过；预览列出三个世界目录；实际执行恢复并通过目录树校验。 |
| 恢复后再次启动 | 成功再次达到 Done 和运行中。 |
| 结束测试 | 再次优雅停服，确认本机 25565 端口关闭。实例和备份保留。 |

没有使用实际 Minecraft 游戏客户端进入世界，也没有异地朋友加入；本机状态查询成功不代表局域网或公网联机已经验证。

## 视觉上的具体问题

1. **空间分配没有服务当前任务。** 运行环境页内容集中在顶部约四分之一，余下是大空白，帮助却压在最下面。首页的任务进度也在底部，主要视野保留旧会话。[运行环境](11-wizard-runtime.png)、[运行会话](01-running-session.png)。建议把当前步骤、推荐值、主要行动和进度组织在相邻区域，键盘提示做简短的固定辅助。
2. **辅助文字过暗，但其中包含必要信息。** 路径、解释、输入占位符和部分底部提示在深色背景上很弱。它们并非都属于可忽略信息。建议提高必要说明的对比度，减少同时显示的提示数量；无需把所有内容都加亮。[运行环境](11-wizard-runtime.png)。
3. **焦点与选中态需要辨认。** 名称字段只有 `›` 和文字变化，版本列表同时有高亮项；运行环境页中 Java 高亮和内存橙色色块同时出现。建议让“当前正在编辑的字段”有更明确、统一的表示，已选值采用次一级样式。[名称](10-wizard-name.png)、[运行环境](11-wizard-runtime.png)。
4. **强调色使用过多。** 标题、边框、路径、快捷键、进度与数值都使用橙色；备份页两个大面板都用强调边框。第一眼难判断哪里是主要动作、哪里是普通信息。建议将强调色集中在当前操作、选择和关键状态。[备份管理](03-backup-manager.png)。
5. **摘要主次倒置，小窗口硬截断。** 详情摘要长 Java 路径占一整行，右侧截断；日志长行也截断，界面没有明显的展开或横向查看提示。联机版本、加入方式和就绪结论应优先于完整路径。[小窗口详情](07-ready-stale-footer.png)。
6. **经典首页缺少直接的运行状态。** 约 80 列时实例行只看到名称、Paper 版本、端口和内存，是否运行要打开详情确认；下面大量位置用于已完成任务的满格进度条。建议把运行状态和主要操作放进实例行，完成任务压缩呈现。[截图](06-classic-small.png)。
7. **产品文案与内部信息混杂。** 中文操作旁出现英文状态、UTC 时间、UUID、byte 游标、RSS 等；日志保留原文合理，但界面自身状态可以统一语言、使用本地时间，并把内部标识放进详情。

也有有效的设计：向导的三步结构、明显的版本选择行、下载字节与速度反馈、停服保存、恢复影响预览，以及恢复后保持停止并要求显式启动，均帮助完成了实际操作。

## 环境因素与最终状态

最初灰白无色来自启动环境的 `NO_COLOR=1`，不是主题本身失效。移除后已验证 Claude 与 DeepSeek 彩色主题切换。最初浏览器画布缩放异常也通过 ttyd 的 DOM 渲染方式解决，没有把该桥接异常算成产品缺陷。字体与终端模拟器仍可能影响中文字形，未将这种差异当成原生 TUI 的确定缺陷。

浏览器入口：http://127.0.0.1:7681/ 。daemon 和 ttyd 保持运行；没有安装后台用户服务。体验配置位于 `/tmp/mc-tui-experience/config.toml`。测试实例 `friends-night` 已停止，备份保留。源码和设计文件未修改；报告与截图位于本目录。

优先建议：先修首次配置和异步结果反馈，再补“朋友如何加入”的明确引导，随后统一状态、改善层级和小窗口显示。继续增加主题不能解决这些旅程断点。
