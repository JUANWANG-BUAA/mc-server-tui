ALPHA

This guide documents the shipped v0.2.0 behavior. The release is unsigned and does not promise production stability or data recovery.

Notice

Applies to v0.2.0 (unsigned alpha pre-release). This guide describes the shipped alpha. It is not a promise of production stability, data recovery, compatibility with every server pack, or support for every Minecraft version.

Notice

Current source only (unreleased): builds after v0.2.0 keep the selected server, next action and resources at the top, with one background progress summary. Console drafts show their target; switching instances blocks submission until you return to the original instance or clear the draft with Esc. The runtime step starts with a summary: Enter continues, F3 or Tab opens settings. F3 expands instance diagnostics or backup evidence; Ctrl-K also exposes these actions. Backup details use local time with an explicit offset, and restore previews explain replacement scope and that later progress is not merged. Management connectivity is separate from Minecraft readiness. These changes are not in the v0.2.0 release.

The TUI relies on a Unix socket and Unix process behavior. Windows is not supported by this release. Use a terminal at least 80×24; 40×12 is usable with reduced chrome.

Java must match the selected Minecraft and server version. The creation flow shows detected runtimes and recommends one, but you remain responsible for the server version, plugins/mods, and client compatibility.

03 / Get started

Install

Release installer

v0.2.0 is a pre-release, so use the tag-specific URL:

Shell
TAG=v0.2.0
curl -fsSL "https://github.com/JUANWANG-BUAA/mc-server-tui/releases/download/$TAG/install.sh" | sh
mc setup
mc

mc setup writes a user configuration, checks Java, installs a launchd or systemd user service when available, starts the daemon, and opens the TUI from mc. To write configuration without installing a background service:

Shell
mc setup --no-service
mc daemon run   # terminal 1
mc tui          # terminal 2

Build from source

The repository pins Rust 1.89.0:

Shell
git clone https://github.com/JUANWANG-BUAA/mc-server-tui.git
cd mc-server-tui
cargo build --workspace
./target/debug/mc setup --dry-run
./target/debug/mc setup
./target/debug/mc

Verify the active version and protocol:

Shell
mc version --json
mc status --json
mc doctor --json
04 / Get started

Create the first server

Start mc, then enter:

TUI
/create

The guided Paper flow asks for:

  1. instance name and Minecraft version;
  2. Java runtime, memory range, and server port;
  3. a review of the artifact, download source, memory, port, and EULA.

New date-based releases such as 26.3 and 26.2 are sorted before legacy 1.21.x releases in the version picker. Choose the exact version your players will use. EULA acceptance is explicit and is never selected automatically.

After submission, use:

TUI
/tasks
/task <number>

to inspect download progress, source, speed, phases, and cancellation.

For a Fabric server:

TUI
/fabric MyFabricServer 1.21.11 --accept-eula

The Fabric path resolves a stable loader and compatible Java, checks the port, and creates a managed instance.

05 / Day to day

Session shell

The default screen is a session shell. Text without a leading slash is sent to the current Minecraft console; slash commands manage the application.

Common commands:

CommandPurpose
/help, F1Show all commands and keys
/instances, /use <number-or-name>List and select an instance
/openOpen the selected instance detail
/start, /stop, /restartStart, gracefully stop, or controlled restart
/logsTail console output in the session
/console <command>Send one command to the Minecraft console
/tasks, /task <n>, /cancel [n]Inspect or cancel durable tasks
/backup, /backupsCreate or manage stopped-world backups
/configEdit four common server.properties values
/players [action] [player]OP, whitelist, ban, pardon, kick, LuckPerms helpers
/rg [-i] [-e] <pattern>Search current and rotated logs
/connect, /monitorInspect join addresses and server state
/mods, /import, /exportAdd-ons and server-pack workflows
/pages, /page <n>, /close [n]Workspace pages
/theme [name], F2Themes
/quitExit the TUI; the server and tasks continue

Useful keys: Enter submit, Tab complete, ←/→ move the cursor, Home/End line boundaries, ↑/↓ history or selection, Ctrl-K command palette, F2 theme, and F1 help.

06 / Day to day

Lifecycle and readiness

  • /start is idempotent and verifies the Java path, server JAR, port, and process identity.
  • /stop sends Minecraft's graceful stop command and waits for the verified process to exit. Timeout does not force-kill Java.
  • /restart requires a verified starting or running process, gracefully stops it, waits for a clean stopped state, then starts the same instance. It does not start a replacement after an unclean stop.
  • Readiness requires the server's Done ( marker. An open port alone is not considered ready.
  • Closing the TUI or daemon does not kill the resident runner or Java process.

The instance detail page (/open) exposes lifecycle controls, console input, logs, process identity, CPU/RSS samples, and alerts. Press R there for a controlled restart and c for configuration.

07 / Day to day

Common configuration

Run:

TUI
/config

The current editor supports MOTD, maximum players, difficulty, and view distance. It shows a diff before writing, preserves unknown keys and comments, and rejects an external file change instead of overwriting it. Saving while the server is running does not restart it. Use /restart or R when you want the new values to take effect.

Raw editing, the complete property catalog, and per-version validation are not implemented. For unsupported properties, edit server.properties while the server is stopped and keep your own backup.

08 / Day to day

Backups and restore

Backups are stopped-world only.

  1. Stop the server and wait for stopped.
  2. Run /backup.
  3. Open /backups and select a verified snapshot.
  4. Press v to verify, then Enter to build a restore plan.
  5. Review affected worlds, added/replaced/removed roots, staging space, and safety steps.
  6. Type the exact RESTORE confirmation and submit.

Restore is transactional and keeps rollback evidence until commit verification. The server remains stopped after restore. Start it explicitly and validate the world with a Minecraft client. No automated online backup or scheduler exists in this release.

09 / Day to day

Players, logs, and workspaces

Examples:

TUI
/players list
/players op Steve
/players allow Alex
/players whitelist-on
/players kick Steve reason

Online-name actions may need Mojang profile lookup and can fail on constrained networks. The TUI reports server responses or timeout errors; it does not pretend the action succeeded.

/rg searches current and one rotated log. /logs shows recent output. /monitor shows game status and online count. CPU/RSS history is local observability, not TPS/MSPT or JVM heap telemetry.

Workspace pages preserve log filters and reading positions. Closing a page does not stop the server.

10 / Day to day

Fabric, add-ons, and server packs

  • /mods search <name> and /mods install <name> install supported Modrinth Paper plugins or Fabric mods, required catalog dependencies, and validated JARs. The instance must be stopped.
  • /import previews a .mrpack or server-pack ZIP. /import <path> --apply stages and verifies compatible mods, plugins, and config; it refuses conflicts, unsafe paths, world/identity data, server.jar, and server.properties.
  • /export <path.zip> creates a server add-on/config bundle with a SHA-256 manifest. It is not a client launcher pack.

Imports do not execute pack scripts and do not prove that the combined plugins/mods will start. Validate after import. Forge/NeoForge and CurseForge file-ID materialization are not implemented.

11 / Operate

CLI

The CLI uses the same typed daemon API:

Shell
mc cli instance list
mc cli instance start <instance-id>
mc cli instance stop <instance-id> --timeout-seconds 20
mc cli instance restart <instance-id> --timeout-seconds 20
mc cli backup create <instance-id>
mc cli backup list <instance-id>
mc cli task list
mc cli modpack inspect /path/server.mrpack

CLI lifecycle output is an observation; a server can still be starting while the command returns. Poll dashboard/detail status or use the TUI until the readiness marker is observed.

12 / Operate

Service, update, and data

Shell
mc service install
mc service status --json
mc service restart
mc service uninstall
mc update status
mc update rollback --dry-run

The user service supervises the daemon. Resident Java runners are intentionally separate. mc service restart restarts the daemon and leaves running servers alone. Uninstall preserves instance data unless a destructive purge option is explicitly used.

mc doctor prints the exact data directory. Instance worlds live under <state>/instances/<uuid>/server/. Do not edit the UUID directory while the server is running. Configuration, socket, state, and cache paths can be overridden in config.toml or with documented environment variables.

13 / Operate

Troubleshooting

Run first:

Shell
mc version --json
mc doctor --json
mc status --json

The instance detail recognizes common startup failures from the current log:

SymptomFirst action
UnsupportedClassVersionErrorSelect Java compatible with the server/MC version
Port bind failureStop the process using the port or choose another port
EULA warningReview and explicitly accept the Minecraft EULA
OutOfMemoryErrorRaise the instance maximum memory within host capacity
Missing/corrupt JARReinstall the locked server build

For unknown failures, use /open and /rg to inspect the full current and rotated logs. Do not blindly force-kill an unknown PID; the supervisor refuses to signal processes whose identity cannot be verified.

If the daemon is unavailable:

Shell
mc service status --json
mc service start
mc doctor --json
14 / Operate

Network exposure

/connect suggests local, LAN, and possible public addresses. It does not prove that a remote friend can connect. Port forwarding, NAT, firewalls, carrier restrictions, and DNS are outside the application's control.

Do not expose an administrative host directly to the internet. Run the manager under a dedicated user, restrict file permissions, keep the daemon socket private, use a firewall, and review plugin/mod permissions. Minecraft server software and third-party code may contain vulnerabilities.

15 / Trust

Evidence and current limitations

The v0.2.0 notes record 217 automatic tests, four PTY suites, protocol checks from v8–v11, a local manifest installer smoke, and a real Paper restart drill. These results do not prove every world, plugin combination, network, or client scenario. A real Minecraft client join and post-restore in-game verification still need to be performed.

Current gaps include Vanilla, existing-directory takeover, complete server.properties editing, online/scheduled backups, Forge/NeoForge, CurseForge file-ID downloads, signed/notarized artifacts, a signed self-updater, state migrations, update-time task draining, and real Linux service validation.
